# Card

The `Card` family provides a structured container for related content. Instead of a large prop API, it relies on composition: a root card plus named slots for title, description, actions, content, and footer.

## Usage guidance

### Slot behavior

- `CardHeader` controls top spacing and adapts when `CardAction` is present.
- `CardContent` is the default body region for any custom layout.
- `CardFooter` adds a top border and tighter alignment for persistent actions or summary metadata.

### Size selection

Choose one card size for a repeated collection whenever possible. Mixing densities inside the same list or dashboard section usually makes the layout feel inconsistent.

### Accessibility

- Use heading text inside `CardTitle` when the card introduces a distinct section of content.
- Keep action labels specific so users can understand the card task without reading the entire body first.
- Avoid turning the entire card into an interactive target unless the full surface is truly a single action.

## Root props

The root component accepts standard `div` props plus the `size` prop. Subcomponents accept standard `div` props and inherit spacing and alignment from the slot they represent.
